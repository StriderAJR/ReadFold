# ReadFold

**From guided reading to fluent reading.**

Изучение японского через чтение с русским разбором. Приложение работает в гостевом режиме;
Google/GitHub через Supabase добавляют синхронизацию между устройствами.

## Запуск

Node.js 22.12+ / 24 LTS, npm:

```sh
npm ci
cp .env.example .env.local
npm run dev
```

Откройте `http://localhost:5173/ReadFold/`. Параметры Supabase необязательны для гостевого режима.
На Windows `run-local.bat` запускает сервер и открывает браузер; остановка — Ctrl+C в его окне.
В `.env.local` укажите только `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`.
Секреты OAuth, service_role и пароль PostgreSQL не используются frontend.

## Реализованные возможности

- Каталог, избранное, недавнее чтение, главы и восстановление позиции.
- Подробный, адаптивный и непрерывный режимы; независимые ruby/furigana, хирагана, ромадзи,
  буквальный/литературный перевод и разбор слов/кандзи/грамматики.
- Оригинальный CC0-рассказ из двух глав, стабильные ID, строгие Zod-схемы и ленивые JSON.
- Отдельные словарные карточки и переходы к вхождениям в тексте.
- Задания на значение, чтение, письменный перевод, кандзи и грамматику; история и интервальные повторения.
- IndexedDB/Dexie: атомарный журнал и outbox, миграции, импорт/экспорт выбранного владельца,
  явный перенос гостевых данных, изолированная локальная диагностика.
- Supabase PKCE, отдельный application UUID, SQL RLS, идемпотентные RPC и повторные попытки синхронизации.
- Production service worker для повторного открытия приложения и загруженных материалов без сети.
- Локальная сборка в `docs/` для GitHub Pages; ручной heartbeat с необязательными Telegram-уведомлениями.

## Проверка

```sh
npm run typecheck
npm run lint
npm test
npm run test:deployment
npm run test:sql
npm run build
npx playwright install chromium
npm run test:e2e
```

На Windows E2E по умолчанию использует установленный Google Chrome; в CI — Playwright Chromium.
Playwright запускает production preview. Реальный OAuth не выполняется в CI: адаптер покрыт моками SDK.
SQL/RLS-проверки запускаются локально в PGlite с минимальной auth-schema, без доступа к production.
Это не заменяет проверку настроек реального Supabase.

## Развёртывание и внешние настройки

Сохранён адрес `https://striderajr.github.io/ReadFold/` и регистр base path. HashRouter обеспечивает
прямые ссылки без серверного fallback. Privacy/Terms и Google verification копируются в dist из public.
Команда `npm run publish:docs` выполняет проверки, собирает приложение и переносит готовые файлы в `docs/`.
На Windows можно запустить `publish-docs.bat` двойным щелчком; окно останется открытым с результатом.
Прежние HTML сохраняются в `.local-tools/pages-backups/`, Markdown и Google verification сохраняются.
После проверки изменений нужен commit и push; Pages должен использовать `master` → `/docs`.
Скрипт не выполняет Git-операции. Доступность Pages при блокировке биллинга требует проверки после push.

Смотрите [точные настройки Pages, OAuth, SQL и heartbeat](docs/deployment.md).
Миграция [202611120001_user_sync.sql](supabase/migrations/202611120001_user_sync.sql) **применена**
к проекту `kkmuehzkvmbmnkzwfxfa` 12 ноября 2026 по явному разрешению владельца, с предоставленным
CA-сертификатом и проверкой TLS. Проверены RLS двух таблиц, две ownership policy, закрытые private RPC
и запрет прямой записи клиентом. Публичный heartbeat возвращает true, anonymous data request получает 401.
Не применяйте эту миграцию повторно. Тестовые пользователи/данные в live-БД не создавались.

На 12 ноября 2026 проходят typecheck, lint, **55 Vitest-тестов**, локальная SQL/RLS-проверка и
**9 Playwright E2E** по production-сборке. Проверены desktop/mobile/dark, отсутствие горизонтального
переполнения читателя на 390px и отсутствие JS page errors в визуальном smoke-test.
Публичные OAuth endpoints Google/GitHub возвращают 302 к соответствующему провайдеру;
интерактивный вход и полный сценарий синхронизации двух устройств ещё требуют проверки реальным аккаунтом.
Подробности: [validation.md](docs/validation.md).

## Ограничения

- Демонстрационная библиотека небольшая; редактура носителем японского языка ещё не проводилась.
- Offline доступны только ранее загруженные главы; очистка данных браузера удаляет локальные изменения.
- Конфликтующие события сохраняются, но текущее значение статуса/настройки выбирается по времени и ID.
  Между устройствами важны корректные часы; локальные записи имеют монотонное время.
- Журнал пока не уплотняется: при большой истории потребуется пагинация локальных выборок и compaction.
- Cloud deletion выполняется по проверенному запросу, автоматической кнопки удаления аккаунта нет.
- Heartbeat не гарантирует предотвращение Supabase Free pause; сброс Actions cache может повторить уведомление.
- Полный Google/GitHub login и multi-device sync требуют проверки реальными аккаунтами; публикация ожидает push
  и переключение Pages. RLS дополнительно проверена локально с двумя тестовыми пользователями.
