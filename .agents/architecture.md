# Архитектура ReadFold

React + Vite, TypeScript strict. `src/domain` содержит Zod-модели, журнал пользовательских событий,
детерминированный планировщик и задания. Domain не импортирует React, Dexie или Supabase.
`src/application` координирует сценарии и синхронизацию. UI находится в `src/ui`.

Адаптеры `src/infrastructure/local`, `supabase` и `content-provider.ts` отвечают за IndexedDB,
OAuth/SQL RPC и валидированный ленивый контент. Интерфейсы AuthService/SyncTransport определены
в domain: будущий ASP.NET Core API может заменить Supabase-адаптер.

IndexedDB — первичный источник изменений: immutable operation и outbox записываются одной транзакцией.
TanStack Query кэширует асинхронные чтения, но не заменяет базу. Zustand хранит состояние сессии.
Гостевые и аккаунтные записи разделены ownerId; перенос гостя требует явного действия.
Журнал сохраняет все конфликтующие события; вычисляемое состояние детерминировано.
Подробнее: [sync.md](sync.md), [data-model.md](data-model.md).

Редактируемые материалы лежат в `content/ja/`: каталог, главы-манифесты с упорядоченными частями,
небольшие группы слов и отдельные карточки кандзи/грамматики. `scripts/build-content.mjs` валидирует
всю коллекцию и собирает JSON в `.local-tools/content/` для dev-сервера и непосредственно в `dist/`
для production-сборки; passthrough-файлы для Vite лежат отдельно в `dist_public/`, а контент не смешивается с ними.
Приложение и агент используют общий индекс `id → файл`.
Чтение главы загружает её и только связанные карточки/вхождения, словарная страница
может загрузить весь выбранный раздел. Zod проверяет данные перед использованием и перед чтением из
локального кэша. `ja/` задаёт границу исходников языка; второй язык пока не реализуется. Японские
ruby-сегменты — подготовленные данные, а не автоматическая транслитерация.

Основная поставка — локальная сборка в `dist` с проверками и перенос готового сайта в `docs/` для
публикации GitHub Pages из ветки. GitHub Actions для сборки приложения не требуется.
HashRouter сохраняет прямые ссылки и обновление страниц под `/ReadFold/`.
Production service worker кэширует только ресурсы того же origin под base path, не OAuth/Supabase.
Загруженные JSON сохраняются отдельно в IndexedDB. Изменение схемы контента требует явной версии.
OAuth redirect вычисляется из origin и base сборки. Адрес сайта и origin сохраняются; ограничения
GitHub на фактический deployment проверяются отдельно. Порядок выпуска: [deployment.md](deployment.md).

Диагностика локальна, отделена от outbox, ограничена белым списком кодов. Секреты не попадают в сборку.
RLS и ownership проверяются PostgreSQL, а не только UI.
