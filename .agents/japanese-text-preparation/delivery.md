# Сборка, метаданные и проверка

[Порядок работы](../japanese-text-preparation.md) · [Формат данных](../book-format.md)

## Идентификаторы и файлы

Используй текущие `bookId` и `chapterId`, если они заданы в каталоге. Если книга новая, согласуй ID из латинских строчных букв, цифр, точек и дефисов и держи их неизменными при правке текста. Предложения нумеруй по порядку, например `<chapter-id>.s001`, `<chapter-id>.s002`; абзацы — `<chapter-id>.p001`. Не переиспользуй ID для другого предложения.

Карточки используют ID `ja:word:<словарная форма>`, `ja:kanji:<иероглиф>` и `ja:grammar:<конструкция>`. Омонимы получают стабильное смысловое уточнение по [правилам словаря](dictionary.md); не объединяй их автоматически. Каталог сохраняет `schemaVersion: 1`, глава и словарь используют `schemaVersion: 2`.

Исходник главы организован по manifest/parts:

```json
{
  "schemaVersion": 2,
  "id": "novel.chapter-01",
  "bookId": "novel",
  "title": "Название главы",
  "parts": ["part-001.json"]
}
```

`part-001.json` содержит объект с `paragraphs`, где каждый абзац имеет `id` и непустой массив `sentences`.
Манифесты и части находятся в `content/ja/books/novel/novel.chapter-01/`; генератор собирает JSON сайта.

Для новой книги метаданные должны честно указывать автора, источник и лицензию. Не указывай CC0 или разрешение на распространение, если это не подтверждено правообладателем. Не добавляй исходный текст книги в README, отчёты или примеры.

## Контроль перед сдачей

Независимый проверяющий (`gpt-6.1-sol`, effort `medium`) работает с правом чтения пакетами по 10–20 предложений. Для **каждого** `sentenceId` сравни итоговый текст и исходные ruby-чтения с зафиксированным черновиком источника, оцени чтения и смысловую точность обоих переводов по японскому `text`; проверь, что часть, абзац и предложение не пропущены и не повторены. По `text` и принятой сегментации проверь все словесные вхождения, включая повторные, и наличие их `wordOccurrences` и словарных карточек. Вычисли набор уникальных кандзи в `text` и сравни его с `kanjiIds` без лишних и пропущенных ID; карточки `isMnemonicPartOnly` в этом списке недопустимы. Отдельно проверь **каждое появление** кандзи в `text`: оно должно быть покрыто сегментом с контекстным `reading`, в том числе там, где в оригинале не было ruby. Прочитай предложение для проверки всех учебно значимых грамматических конструкций, включая частицы и повторы, и их контекстных `grammarOccurrences`; автоматическая проверка ссылок эту полноту не доказывает. Новую карточку кандзи проверяй отдельно: все части видны в знаке, а мнемоника связывает их количество и положение со значением без выдуманной этимологии. Фиксируй замечания как `sentenceId` или ID карточки + фрагмент + вид пропуска + ответственный этап. Исправления поручает координатор профильному агенту; затем проверяющий повторно читает исправления. Вопрос к точности источника возвращается агенту источника, который при необходимости сверяет HTML.

При общей сдаче используй результат сверки HTML агентом источника и проверенный JSON для следующих пунктов:

- число и последовательность абзацев и предложений, отсутствие пропусков и дублей;
- каждое `segments[].text` точно восстанавливает исходное `text`; чтения из HTML ruby сохранены в соответствующих сегментах;
- если добавлены `wordOccurrences[].furigana`, `grammarOccurrences[].roleSegments` или `explanationSegments` карточки, их текст точно восстанавливает соответственно `surface`, `role` и `explanation`; чтение `furigana` относится к одному кандзи либо непрерывной группе кандзи;
- у каждого предложения есть все обязательные поля, русский перевод и хотя бы одна запись `wordOccurrences` с непустыми `hiragana` и `romaji` контекстной формы;
- ID карточек и структурных элементов уникальны; повторные вхождения слова или грамматики сохранены отдельными объектами, а `wordOccurrences[].wordId`, `kanjiIds`, `grammarOccurrences[].grammarId` и связи справочника разрешаются;
- у каждого элемента `grammarOccurrences` есть непустая контекстная строка `role`; она объясняет фрагмент текущего предложения и не повторяет `explanation` словаря;
- каждый кандзи в `grammarOccurrences[].role`, `grammar.explanation` и `grammar.examples[].text` покрыт сегментом с проверенным `reading` в `roleSegments`, `explanationSegments` или `segments` примера соответственно; в новых заголовках грамматики нет кандзи без поддерживаемой фуриганы;
- каждый новый ID имеет содержательную запись в нужном разделе словаря; у новых кандзи проверены `components`, переводы или образы всех частей в `componentMeanings` и связанная с ними `mnemonic` либо явно указан пробел для ручной проверки;
- `sentenceCount` в каталоге равен фактическому числу предложений;
- нет неизвестных полей, комментариев внутри JSON, Markdown-обёрток или завершающих запятых.

Запусти `npm run content:build` и `npm run test:content`, чтобы проверить всю коллекцию и получить dev-данные. Production JSON создаёт `npm run build` непосредственно в `dist/`. Для адресной проверки используй `npm run content:entity -- <id>`. В итоговом отчёте укажи исходные файлы, число абзацев и предложений и нерешённые вопросы. Не заявляй, что материал полностью проверен, если в отчёте остались сомнительные чтения или границы.
