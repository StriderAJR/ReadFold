# Сборка, метаданные и проверка

[Порядок работы](../japanese-text-preparation.md) · [Формат данных](../book-format.md)

## Идентификаторы и файлы

Используй текущие `bookId` и `chapterId`, если они заданы в каталоге. Если книга новая, согласуй ID из латинских строчных букв, цифр, точек и дефисов и держи их неизменными при правке текста. Предложения нумеруй по порядку, например `<chapter-id>.s001`, `<chapter-id>.s002`; абзацы — `<chapter-id>.p001`. Не переиспользуй ID для другого предложения.

Карточки используют ID `ja:word:<словарная форма>`, `ja:kanji:<иероглиф>` и `ja:grammar:<конструкция>`. Омонимы получают стабильное смысловое уточнение по [правилам словаря](dictionary.md); не объединяй их автоматически. Каталог сохраняет `schemaVersion: 1`, глава и словарь используют `schemaVersion: 2`.

JSON главы должен иметь вид:

```json
{
  "schemaVersion": 2,
  "id": "novel.chapter-01",
  "bookId": "novel",
  "title": "Название главы",
  "paragraphs": [
    {
      "id": "novel.chapter-01.p001",
      "sentences": []
    }
  ]
}
```

Для новой книги метаданные должны честно указывать автора, источник и лицензию. Не указывай CC0 или разрешение на распространение, если это не подтверждено правообладателем. Не добавляй исходный текст книги в README, отчёты или примеры.

## Контроль перед сдачей

Проверь по исходному HTML и отображаемому тексту:

- число и последовательность абзацев и предложений, отсутствие пропусков и дублей;
- каждое `segments[].text` точно восстанавливает исходное `text`;
- у каждого предложения есть все обязательные поля, русский перевод и хотя бы одна запись `wordOccurrences` с непустыми `hiragana` и `romaji` контекстной формы;
- ID карточек и структурных элементов уникальны; повторные вхождения слова или грамматики сохранены отдельными объектами, а `wordOccurrences[].wordId`, `kanjiIds`, `grammarOccurrences[].grammarId` и связи справочника разрешаются;
- у каждого элемента `grammarOccurrences` есть непустая контекстная строка `role`; она объясняет фрагмент текущего предложения и не повторяет `explanation` словаря;
- каждый новый ID имеет содержательную запись в нужном разделе словаря; у новых кандзи проверены `components`, переводы или образы всех частей в `componentMeanings` и связанная с ними `mnemonic` либо явно указан пробел для ручной проверки;
- `sentenceCount` в каталоге равен фактическому числу предложений;
- нет неизвестных полей, комментариев внутри JSON, Markdown-обёрток или завершающих запятых.

Запусти проверку проекта: `npm test -- src/domain/content.test.ts`. Если есть скрипт или валидатор загрузки контента, проверь им главу, каталог и словарь вместе. В итоговом отчёте укажи файлы, число абзацев и предложений, использованные пакеты и нерешённые вопросы. Не заявляй, что материал полностью проверен, если в отчёте остались сомнительные чтения или границы.
