# Формат книг v2

Каталог public/books/catalog.json сохраняет schemaVersion: 1: массив метаданных книг с id, title,
author, description, originalLanguage, translationLanguage, difficulty, tags, cover (эмодзи), license,
source и chapters. Необязательное translatedTitle содержит переведённое название. Каждая глава каталога
содержит id, title, path, sentenceCount. Каталог не содержит текста глав: JSON главы загружается отдельно
относительно Vite base URL /ReadFold/.

Глава имеет schemaVersion: 2, id, bookId, title, paragraphs. Абзац содержит id и sentences.
Предложение содержит id, text, segments, hiragana, romaji, literal, natural, wordOccurrences,
kanjiIds и grammarOccurrences. Сегмент {text, reading?} задаёт ruby явно; конкатенация text всех сегментов
обязана совпадать с предложением. hiragana сохраняет орфографию частиц は/へ/を; romaji передаёт их
произношение wa/e/o. Чтения и переводы готовятся редактором, а не вычисляются приложением.

## Словарная карточка и вхождение

dictionary.json имеет schemaVersion: 2, words, kanji, grammar — независимые справочники.
Словарная карточка слова: id, surface, dictionaryForm, reading, romaji, partOfSpeech, meanings.
reading и romaji относятся к словарной форме; meanings объясняет значения карточки вне конкретной фразы.

wordOccurrences содержит каждое контекстное вхождение, в том числе повторы одного wordId в предложении.
Поля вхождения: {wordId, surface, hiragana, romaji, meaning, inflection?, role?}. surface — точная форма
в тексте, hiragana и romaji — чтение именно этой формы, meaning — её значение здесь, inflection — изменение
формы, role — функция в текущей фразе. Например, карточка 行く хранит reading: いく и romaji: iku, а вхождение
行きます хранит hiragana: いきます и romaji: ikimasu. Чтения карточки нельзя подставлять вместо контекстных.

grammarOccurrences: [{grammarId, role}] связывает каждое употребление конструкции с непустой строкой её
контекстной роли. При повторе конструкции допустим повтор grammarId с отдельной ролью для каждого
употребления. Общее объяснение, образование и примеры принадлежат карточке грамматики. Старые поля words,
grammarIds и grammarRoles в главе v2 отсутствуют. kanjiIds остаётся списком уникальных ссылок на кандзи.

Иероглиф: id, character, meanings, on, kun, components, wordIds, необязательные componentMeanings и mnemonic.
components — визуальные составляющие для запоминания; componentMeanings задаёт русские переводы или
ассоциативные образы всех составляющих и должен точно совпадать с components по ключам. mnemonic связывает
образы со значением. Это учебная мнемоника, а не утверждение об этимологии.

Грамматика: id, title, explanation, examples: [{text, translation}], relatedIds. Примеры также поддерживают
необязательные hiragana, romaji, literal, natural и segments. При наличии segments их непустой массив
должен точно восстанавливать text. В демо все примеры содержат эти слои; примеры только с text и translation
тоже допустимы.

## Стабильные ID

ID сущностей содержат языковой код, правильный тип и основу: ja:word:朝, ja:kanji:朝, ja:grammar:topic.
Основа слова — его японская словарная форма с сохранением написания; основа кандзи — сам иероглиф;
основа грамматики — устойчивое краткое имя конструкции. Unicode допустим в основе ID сущности.
ID книг, глав, абзацев и предложений сохраняют прежний формат латинских букв, цифр, точек и дефисов.

Одна и та же флексия с тем же значением ссылается на существующую карточку. Для омонимов с разными значениями
или лексическими функциями используется устойчивое смысловое уточнение после двоеточия:
ja:word:ある:exist и ja:word:ある:indefinite; ja:word:つく:breath, ja:word:つく:rank,
ja:word:つく:notice. Уточнение описывает смысл, а не номер главы или порядок. Не объединяй такие карточки
по одному написанию или чтению. При создании омонима уже существующий стабильный ID сохраняется.

Все словарные ID глобально уникальны; пользовательское состояние связывается с общим entityId.
ID не меняется при редактуре названия или текста. Новое несовместимое содержание получает новый ID.
Полная таблица старых и новых ID: [entity-id-migration.md](entity-id-migration.md); машинная таблица:
src/domain/entity-id-migration.ts. Таблица постоянна: старые операции продолжают приходить с других устройств.
Старые события журнала не переименовываются и не удаляются, их ID сущности сопоставляются при чтении.

## Проверки

Zod-схемы и типы экспортируются из src/domain/content.ts; неизвестные поля запрещены. Схемы проверяют тип
префикса, уникальность карточек и ID структуры главы, внутренние ссылки справочника и корректность сегментов.
validateChapterReferences проверяет ссылки всех вхождений и кандзи, принадлежность главы книге и число
предложений. Повторы слов и грамматики сохраняются как отдельные вхождения, а не удаляются как дубли ID.
Загрузчик обязан проверить словарь и главу, в том числе при чтении кэша. Версия 2 отделяет несовместимые
данные от кэша формата 1.

npm test -- src/domain/content.test.ts. Все ссылки должны разрешаться, ruby восстанавливать исходный текст.
