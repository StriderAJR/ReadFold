# Подготовка японской главы для ReadFold

Инструкция для редактора или ИИ-агента, который преобразует одну исходную HTML-главу ранобэ в JSON главы ReadFold. Формат полей описан в [book-format.md](book-format.md), точные схемы — в `src/domain/content.ts`.

## Результат

На входе — один HTML-файл на одну главу. На выходе — один файл главы `books/<book-id>/<chapter-id>.json`, необходимые дополнения к `books/dictionary.json` и обновление каталога с путём главы и `sentenceCount`. Не объединяй главы или всю книгу в один файл.

## Порядок работы

1. [Извлеки авторский текст из HTML](japanese-text-preparation/source-text.md): проверь заголовок, абзацы, ruby, порядок и границы предложений.
2. [Разметь предложения, слова и кандзи](japanese-text-preparation/sentence-analysis.md): сохрани точный текст, чтения, переводы и контекстные ссылки на словарь.
3. [Выдели грамматические конструкции](japanese-text-preparation/grammar.md): отметь учебно значимые конструкции и объясни их роль в предложении.
4. [Заполни словарь](japanese-text-preparation/dictionary.md): для каждого нового ID создай подробную карточку слова, кандзи или грамматики.
5. [Собери и проверь результат](japanese-text-preparation/delivery.md): соблюдай стабильность ID, обнови метаданные, проверь JSON и отчёт.

Читай соответствующий раздел перед выполнением шага; требования этих разделов относятся к одной главе и одному итоговому набору файлов.

## Большие главы

Не генерируй и не выводи весь файл одним ответом, если это грозит обрезанием или потерей точности.

1. Прочитай HTML целиком для понимания сюжета, персонажей, регистра речи и структуры абзацев. Не переписывай его целиком в ответ.
2. Разбей главу по исходным абзацам на последовательные пакеты примерно по 20–40 предложений (или меньше, если предложения длинные). Не дели предложение между пакетами. Зафиксируй номера первого и последнего исходного предложения в каждом пакете.
3. Веди общий журнал: `sentenceIndex → стабильный sentence id`, новые слова, чтения неоднозначных имён/терминов, кандзи и грамматика. Перед следующим пакетом передавай этот журнал, чтобы не менять IDs и трактовки. Сохраняй контекст предыдущего пакета для связности перевода.
4. Обрабатывай пакеты строго по порядку. Каждый пакет возвращай как валидный фрагмент JSON (например, список абзацев), без обрамляющего Markdown, если результат будет автоматически склеиваться. Не разрывай JSON-объекты и строки на границах пакетов.
5. После последнего пакета собери один JSON-файл главы, сверив число предложений и порядок с извлечённым HTML-текстом. Отдельно верни изменения словаря и обновлённые метаданные каталога. Если среда умеет писать файлы, записывай пакеты в рабочие файлы, затем собирай итог; не полагайся на длинную историю чата как на единственное хранилище.

## Краткий шаблон задания агенту

> Преобразуй приложенный японский HTML-файл одной главы в формат ReadFold по `.agents/japanese-text-preparation.md` и всем связанным с ним разделам. Сохрани каждое исходное предложение ровно один раз и в исходном порядке. Обрабатывай большую главу последовательными пакетами по 20–40 предложений с общим журналом IDs и терминов. В каждом элементе `wordOccurrences` заполни `surface`, `hiragana`, `romaji` и контекстное значение; словарные формы и их чтения оставь в карточках. Используй ID `ja:word:<японская форма>` и смысловые уточнения для омонимов, сохраняя их раздельные карточки. Подготовь JSON главы формата 2, подробные записи `books/dictionary.json` для каждого нового слова, кандзи и грамматической конструкции и обновление `sentenceCount`/пути каталога. Для каждого вхождения конструкции создай `grammarOccurrences: [{grammarId, role}]` с пояснением её роли в конкретном предложении; общие правила оставь в словаре. Для новых кандзи распиши визуальные части, их русские переводы или образы и мнемонику; сомнительное оставь на ручную проверку без выдумок. Проверь ссылки, точное восстановление текста сегментами и лицензию. Сохраняй результат в файлы, если доступна файловая система; нерешённые вопросы перечисли отдельно.
