# Подготовка японской главы для ReadFold

Инструкция для координатора и отдельных ИИ-агентов, которые преобразуют одну японскую HTML-главу с ruby-разметкой в исходники ReadFold. Если глава получена как обычный текст, применяй тот же формат, но проверяй чтения вручную. Формат полей описан в [book-format.md](book-format.md), точные схемы — в `src/domain/content.ts`.

## Результат

На входе — один HTML-файл на одну главу. Исходники сохраняй в `content/ja/`: метаданные — в `catalog.json`, глава — в каталоге `books/<book-id>/<chapter-id>/` с манифестом и одной или несколькими частями, новые карточки — в небольших группах слов или отдельных файлах кандзи/грамматики. JSON для dev создаётся в `.local-tools/content/`, production JSON — в `dist/`; эти каталоги вручную не редактируй.

## Последовательные этапы и передача результата

Для каждой главы назначь отдельного агента на источник, слова, перевод, ссылки на кандзи, зрительный разбор кандзи, грамматику и независимую проверку. Этапы **зависимы**: передавай следующему агенту принятый JSON предыдущего; не запускай их параллельно на одном файле. Координатор проверяет результат и передаёт право записи в файл главы только одному агенту за раз. Если отдельные агенты недоступны, выполни те же этапы последовательно и проверь каждый перед переходом к следующему.

Задавай модель и effort при **запуске** каждого агента, а не только текстом задания. Если среда не позволяет выбрать их точно, укажи фактически применённые настройки в отчёте; не утверждай, что требуемая модель использована, без подтверждения.

| Этап | Модель | Effort | Единица содержательной работы |
| --- | --- | --- | --- |
| Источник | `gpt-6-luna` | `medium` | вся глава для сверки, части JSON по абзацам |
| Слова и чтения | `gpt-6.1-sol` | `medium` | 10–20 предложений, каждое отдельно |
| Перевод | `gpt-6.1-sol` | `medium` | 10–20 предложений, каждое отдельно |
| Ссылки и карточки кандзи | `gpt-6.1-sol` | `medium` | 10–20 предложений; карточка на уникальный знак |
| Зрительные части и мнемоника | `gpt-6.1-sol` | `high` | **один кандзи на вызов агента** |
| Грамматика | `gpt-6.1-sol` | `medium` | 10–15 предложений, каждое отдельно |
| Независимая проверка | `gpt-6.1-sol` | `medium` | 10–20 предложений и новые карточки по одной |

Промежуточные части храни в `.local-tools/japanese-text-preparation/<chapter-id>/part-NNN.json`, отдельно от генерируемого `.local-tools/content/`. Это рабочий JSON, а не валидная итоговая глава: схема требует непустой `wordOccurrences` и оба других поля разметки. Не включай части в манифест до завершения всех этапов. Перед началом проверь Git status и сохрани существующие правки.

1. **Источник — [source-text.md](japanese-text-preparation/source-text.md).** Только этот агент открывает оригинальный HTML. Он читает главу целиком, извлекает заголовок, абзацы и предложения в исходном порядке, сохраняет видимый текст, пунктуацию и имеющиеся ruby-чтения. Создаёт черновые части с полями предложения `id`, `text`, `segments`; остальные поля предложения пока отсутствуют. Сам сверяет начало, конец, число и порядок предложений с оригиналом, а конкатенацию `segments[].text` — с `text`. Передаёт журнал ID, диапазонов и неоднозначных границ. После приёмки текст и структура зафиксированы; следующие агенты работают по черновику, не открывая HTML.
2. **Слова и чтения — [sentence-analysis.md](japanese-text-preparation/sentence-analysis.md#слова) и [dictionary.md](japanese-text-preparation/dictionary.md#слова).** В каждом предложении найди **все** слова и междометия, включая повторы и уже известные словарю. Заполни `wordOccurrences`, полные `hiragana` и `romaji` предложения и недостающие `segments[].reading` для **каждого** кандзи без ruby. Переиспользуй ID той же словарной формы и значения; при отсутствии записи создай карточку в `content/ja/dictionary/words/`. Поиск веди точечно по исходным группам слов: сначала найди кандидатов по ID, написанию или словарной форме, затем прочитай только найденные JSON-объекты; не загружай все группы в контекст. Можно уточнить границы `segments`, сохраняя точный `text` и чтения из HTML.
3. **Перевод — [sentence-analysis.md](japanese-text-preparation/sentence-analysis.md#перевод).** Для каждого предложения отдельно заполни `literal` — понятный учебный перевод, близкий к японской структуре, и `natural` — естественный русский перевод. Опирайся на принятые слова и чтения; не меняй их и авторский текст. Передай замеченные ошибки координатору.
4. **Ссылки и карточки кандзи — [sentence-analysis.md](japanese-text-preparation/sentence-analysis.md#кандзи) и [dictionary.md](japanese-text-preparation/dictionary.md#кандзи).** Для каждого предложения извлеки из `text` все уникальные кандзи в порядке первого появления. Заполни `kanjiIds`, переиспользуй карточки и создай недостающие с точными значениями, чтениями и `wordIds`. Пока оставь `components: []` и не создавай мнемонику: это следующий этап. Если знак уже есть как `isMnemonicPartOnly`, для употребления в тексте дополни его проверенными чтениями и сними этот признак. Не меняй предыдущие слои.
5. **Зрительный разбор и мнемоника — [dictionary.md](japanese-text-preparation/dictionary.md#зрительные-части-и-мнемоника).** Вызывай `gpt-6.1-sol` с effort `high` **отдельно для каждого нового знака**. Передай только его знак, значения и текущую карточку, без предложений главы и других кандзи для разбора. Агент выбирает видимые части для запоминания, заполняет `components`, `componentMeanings` и короткую связанную `mnemonic`. Переиспользует карточки уже известных частей; каждый новый знаковый элемент координатор ставит в очередь отдельным вызовом как `ja:kanji:<знак>` с `isMnemonicPartOnly: true`, без чтений и `wordIds`. Словесный зрительный образ остаётся подписью в `componentMeanings`, а не отдельной карточкой.
6. **Грамматика — [grammar.md](japanese-text-preparation/grammar.md) и [dictionary.md](japanese-text-preparation/dictionary.md#грамматика).** Для каждого предложения найди все конструкции, подлежащие учебному разбору, включая повторы. Заполни `grammarOccurrences` с отдельной контекстной `role` для каждого употребления. Добавь фуригану для всех кандзи в ролях, объяснениях и примерах. Переиспользуй существующие ID или создай карточки в `content/ja/dictionary/grammar/`. Если разбор расходится с переводом, сообщи координатору; не переписывай чужой слой молча.
7. **Независимая проверка — [delivery.md](japanese-text-preparation/delivery.md).** Отдельный агент с правом чтения сверяет каждое предложение с зафиксированным черновиком источника и проверяет полноту всех слоёв. Новые карточки кандзи проверяет по одной: части должны быть видимы, а мнемоника — связывать их со значением. Сообщает `sentenceId` или ID карточки, фрагмент, проблему и ответственный этап. Координатор возвращает замечания профильному агенту и повторяет проверку исправлений. HTML повторно открывает только агент источника, если найден вопрос к тексту, границе или ruby.

После приёмки координатор переносит проверенные части в `content/ja/books/<book-id>/<chapter-id>/`, обновляет манифест и каталог, запускает проверки из [delivery.md](japanese-text-preparation/delivery.md). Черновик источника сохраняй до конца проверки для сравнения; не копируй в итоговые файлы служебные поля и отчёты.

## Полнота разбора каждого предложения

В **каждом** предложении перечисляй все встретившиеся слова в `wordOccurrences`, все уникальные встреченные кандзи в `kanjiIds` и все встретившиеся грамматические конструкции в `grammarOccurrences`. Повтор в предыдущем предложении, главе или словаре не освобождает от контекстной ссылки: переиспользуй существующий ID и запиши новое вхождение в данных текущего предложения. Если слово или конструкция встречается в одном предложении несколько раз, добавь отдельный объект для каждого употребления; `kanjiIds` содержит каждый знак один раз. Не ограничивай разбор новыми для словаря единицами. Каждый кандзи в `text` должен быть покрыт сегментом с непустым `reading`, даже если в оригинале нет ruby; `kanjiIds` и общее `hiragana` предложения не заменяют фуригану на строке. Перед сдачей сверяй все три списка и покрытие чтением с японским текстом **каждого** предложения, включая начало главы и повторяющиеся фразы. Правила сегментации и контекстных ролей описаны в разделах [слов и кандзи](japanese-text-preparation/sentence-analysis.md) и [грамматики](japanese-text-preparation/grammar.md).

## Большие главы

Не генерируй и не выводи весь файл одним ответом, если это грозит обрезанием или потерей точности.

1. Агент источника читает HTML целиком и делит главу по исходным абзацам на последовательные части примерно по 20–40 предложений или меньше для длинных предложений. Не дели предложение между частями. Зафиксируй исходные номера первого и последнего предложения каждой части.
2. Агентам слов, перевода, ссылок на кандзи, грамматики и проверки передавай пакеты по абзацам примерно по 10–20 предложений; для грамматики — 10–15. Пакет экономит вызовы, но анализируй и проверяй **каждое предложение отдельно**. Не дублируй запись соседнего предложения ради контекста.
3. Передавай только принятый JSON нужного пакета и краткий журнал `sentenceIndex → sentenceId`, стабильных ID и неоднозначных чтений. Не передавай всю главу повторно. Соседний контекст запрашивай только при конкретной неоднозначности значения, чтения или пропущенного подлежащего; он доступен лишь для чтения. Агент мнемоники получает один кандзи без контекста главы.
4. Каждый профильный агент проходит все части по порядку и заполняет только свой слой. После этапа координатор сверяет список частей и число предложений с журналом. JSON-файлы частей должны быть целыми валидными JSON, без Markdown-обёртки и разрывов объектов.
5. После независимой проверки перенеси части в исходники главы, сверь число предложений и порядок, обнови список частей и `sentenceCount` каталога. Не создавай вручную собранный JSON главы; его выдаст генератор.

## Краткий шаблон задания агенту

> Подготовь японскую главу по `.agents/japanese-text-preparation.md`. Последовательно назначь агентов источника (Luna medium), слов и чтений (Sol medium), перевода (Sol medium), ссылок и карточек кандзи (Sol medium), зрительного разбора одного кандзи за вызов (Sol high), грамматики (Sol medium) и независимой проверки (Sol medium). Задай модель и effort при запуске. Только источник открывает HTML; остальные получают принятый JSON нужного пакета и краткий журнал ID. Каждый агент заполняет свой слой, переиспользует карточки и создаёт недостающие. Проверяющий указывает пропуски по `sentenceId` или ID карточки, координатор возвращает их ответственному этапу. После приёмки собери исходники, обнови манифест и `sentenceCount`, запусти `npm run content:build` и `npm run test:content`, проверь ссылки, текст сегментов и лицензию. Не правь сгенерированные файлы в `.local-tools/content/`, `dist/` и `dist_public/`. Укажи число предложений, результаты проверок и нерешённые вопросы.
