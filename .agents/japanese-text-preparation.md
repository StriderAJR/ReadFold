# Подготовка японской главы для ReadFold

Инструкция для редактора или ИИ-агента, который преобразует одну исходную HTML-главу ранобэ в исходники ReadFold. Формат полей описан в [book-format.md](book-format.md), точные схемы — в `src/domain/content.ts`.

## Результат

На входе — один HTML-файл на одну главу. Исходники сохраняй в `content/ja/`: метаданные — в `catalog.json`, глава — в каталоге `<book-id>/<chapter-id>/` с манифестом и одной или несколькими частями, новые карточки — в небольших группах слов или отдельных файлах кандзи/грамматики. JSON для dev создаётся в `.local-tools/content/`, production JSON — в `dist/`; эти каталоги вручную не редактируй.

## Порядок работы

1. [Извлеки авторский текст из HTML](japanese-text-preparation/source-text.md): проверь заголовок, абзацы, ruby, порядок и границы предложений.
2. [Разметь предложения, слова и кандзи](japanese-text-preparation/sentence-analysis.md): сохрани точный текст, чтения, переводы и контекстные ссылки на словарь.
3. [Выдели грамматические конструкции](japanese-text-preparation/grammar.md): отметь учебно значимые конструкции и объясни их роль в предложении.
4. [Заполни словарь](japanese-text-preparation/dictionary.md): для каждого нового ID создай подробную карточку слова, кандзи или грамматики.
5. [Собери и проверь результат](japanese-text-preparation/delivery.md): соблюдай стабильность ID, обнови манифест и каталог, запусти `npm run content:build` и `npm run content:entity -- <id>` для адресной проверки карточки.

Читай соответствующий раздел перед выполнением шага; требования этих разделов относятся к одной главе и одному итоговому набору файлов.

## Большие главы

Не генерируй и не выводи весь файл одним ответом, если это грозит обрезанием или потерей точности.

1. Прочитай HTML целиком для понимания сюжета, персонажей, регистра речи и структуры абзацев. Не переписывай его целиком в ответ.
2. Разбей главу по исходным абзацам на последовательные пакеты примерно по 20–40 предложений (или меньше, если предложения длинные). Не дели предложение между пакетами. Зафиксируй номера первого и последнего исходного предложения в каждом пакете.
3. Веди общий журнал: `sentenceIndex → стабильный sentence id`, новые слова, чтения неоднозначных имён/терминов, кандзи и грамматика. Перед следующим пакетом передавай этот журнал, чтобы не менять IDs и трактовки. Сохраняй контекст предыдущего пакета для связности перевода.
4. Обрабатывай пакеты строго по порядку. Каждый пакет возвращай как валидный фрагмент JSON (например, список абзацев), без обрамляющего Markdown, если результат будет автоматически склеиваться. Не разрывай JSON-объекты и строки на границах пакетов.
5. После последнего пакета сохрани последовательные `part-NNN.json` в исходниках главы, сверив число предложений и порядок с извлечённым HTML-текстом. Обнови список частей и `sentenceCount` каталога. Не создавай вручную собранный JSON главы; его выдаст генератор.

## Краткий шаблон задания агенту

> Преобразуй приложенный японский HTML-файл главы в исходники ReadFold по `.agents/japanese-text-preparation.md` и связанным разделам. Сохрани каждое предложение ровно один раз и в исходном порядке. Большую главу дели на последовательные части по 20–40 предложений, не разрывая абзацы и предложения. Заполняй контекстные `wordOccurrences` и `grammarOccurrences`; используй `ja:word:<форма>`, `ja:kanji:<знак>`, `ja:grammar:<конструкция>` и смысловые уточнения для омонимов. Для новых карточек создай небольшие исходные файлы под `content/ja/dictionary/`. Обнови манифест и `sentenceCount`, затем запусти `npm run content:build`, `npm run test:content` и проверь ссылки, текст сегментов и лицензию. Не правь сгенерированные файлы в `.local-tools/content/`, `dist/` и `dist_public/`. Нерешённые вопросы перечисли отдельно.
