# ReadFold

ReadFold — веб-приложение для изучения иностранных языков через чтение с подробным разбором текста.
Первый язык — японский; переводы и объяснения — на русском. Предусматривать расширение на другие языки.

## Стек

React + TypeScript + Vite; Tailwind CSS + shadcn/ui; React Router; Zustand; TanStack Query;
Dexie.js + IndexedDB; Supabase Auth + PostgreSQL; i18next; Zod; Vitest + Playwright;
GitHub Pages + GitHub Actions.

## Архитектура

- Offline-first и local-first persistence: надёжно сохранять изменения локально до отправки на сервер.
- Разделять UI, domain logic и infrastructure.
- Держать Supabase за интерфейсами репозиториев и сервисов; модель приложения независима от Supabase и UI.
- Расширять языки без ненужных абстракций.
- Синхронизация не должна терять пользовательские изменения при конфликтах, повторах и работе нескольких устройств.
- Предпочитать минимальную сложность и проверяемые решения.

## Правила кода

- TypeScript strict. Не использовать `any` без явного обоснования.
- Комментарии в коде только на английском.
- Минимальные необходимые изменения; без несвязанных рефакторингов и чрезмерно больших компонентов.
- Аргументы вызовов по возможности размещать в одной строке; переносить преимущественно после 120 символов.
- В условных конструкциях использовать фигурные скобки.
- Не добавлять зависимости без необходимости.

## Multi-agent workflow

Для крупных задач главный агент:

1. Анализирует требования и критерии готовности.
2. Разбивает работу на этапы.
3. Определяет зависимости.
4. Выделяет действительно независимые задачи.
5. Делегирует подходящим специализированным субагентам, если объём оправдывает координацию.
6. Назначает непересекающиеся границы записи по файлам или модулям.
7. Получает результаты и сведения о проверках.
8. Проверяет и интегрирует изменения.
9. Запускает необходимые тесты.
10. Исправляет проблемы и проверяет конечную целостность проекта.

Главный агент отвечает за общий результат. Роли: frontend, data, backend, sync, testing, reviewer.
Определения — `.codex/agents/`; детали — `docs/agent-workflow.md`.
Обычно использовать 2 субагента, максимум 3 одновременно, не считая координатора.
Не делегировать мелкие операции, если координация дороже самостоятельного выполнения.
Не запускать агентов с пересекающимися файлами записи; зависимые шаги выполнять последовательно.
Не создавать вложенные цепочки без необходимости.
Передавать ограниченный контекст: конкретную задачу, входные данные, границы файлов и критерии готовности,
а не полную историю или огромный исходный промпт. Требовать краткий результат с файлами, проверками и рисками.
Если multi-agent недоступен, работать последовательно; не имитировать его скриптами или процессами.

## Экономия контекста и проверки

- Использовать `rg` и точечное чтение; не перечитывать весь репозиторий без необходимости.
- Не передавать субагентам полную историю обсуждений; не дублировать одинаковое исследование.
- Не генерировать большие отчёты после мелких операций.
- Во время разработки предпочитать точечные проверки; не запускать весь набор после каждой правки CSS.
- Перед завершением этапа выполнять полный применимый набор проверок; явно отмечать отсутствующие проверки.
- Не использовать High reasoning effort для рутинных задач; выбирать минимально достаточные модель и effort.
- Не использовать Astra Pro без явного указания пользователя.
