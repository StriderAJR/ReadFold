# Агенты и делегирование

## Использование при реализации ReadFold

В ходе реализации 12 ноября 2026 все шесть ролей доступны через native spawn и использованы:
data — контент/схемы, sync — Dexie/outbox, backend — Auth/RLS, frontend — UI,
testing — E2E, reviewer — независимая проверка. Одновременно работали до трёх субагентов.
Конфигурация `.codex/` сохранена; границы файлов и общие контракты согласовывались перед делегированием.
Фактические результаты проверок — [validation.md](validation.md).

## Исходная подготовка инфраструктуры

Подготовлено для `codex-cli 0.167.0-alpha.4.1`, проверка 2026-11-12.
Multi-agent отмечен как stable и включён; инструменты субагентов доступны в текущей сессии.
`.codex/config.toml` явно включает `agents.enabled` и ограничивает
`agents.max_concurrent_threads_per_session` до 3 (координатор не учитывается).
Используется актуальное имя лимита, а не legacy alias `max_threads`.
Роли — самостоятельные TOML в `.codex/agents/` с name, description и developer_instructions.

| Роль | Область | Модель | Effort |
| --- | --- | --- | --- |
| frontend | UI, reader, accessibility, responsive layout, i18next | gpt-6-luna | low |
| data | Domain, book JSON, Zod, словарь, прогресс, повторения | gpt-6.1-sol | medium |
| backend | Supabase, PostgreSQL, migrations, RLS, OAuth, profiles | gpt-6.1-sol | medium |
| sync | Dexie, IndexedDB, outbox, конфликты, гостевые данные | gpt-6.1-sol | medium |
| testing | Vitest, Playwright, unit/integration/E2E/regression | gpt-6-luna | low |
| reviewer | Код, архитектура, безопасность, потеря данных, покрытие | gpt-6.1-sol | medium |

Модели и effort присутствуют в bundled catalog CLI; доступ аккаунта проверяется при запуске.
Прочие субагенты по умолчанию используют Luna/low. Модель координатора наследуется из пользовательских настроек.
Глобальные настройки, provider, MCP и sandbox не меняются. Reviewer получает запрет на редактирование
как инструкцию; это не отдельный read-only sandbox.

## Передача задачи

Обычно использовать 2, максимум 3 субагента для независимых существенных задач.
Передавать цель, необходимые решения и контракты, разрешённые файлы, запреты, критерии готовности и проверки.
Не копировать полную историю и большое исходное ТЗ.

Пример: «Роль frontend. Реализуй согласованный экран только в перечисленных UI-файлах.
Используй приложенный контракт, не меняй storage и domain. Критерии: состояния загрузки/ошибки
и клавиатурная навигация. Верни файлы, результаты точечных проверок и риски».

Координатор сначала согласует общие контракты, затем разделяет файлы записи.
Зависимые задачи выполняются последовательно. При необходимости изменить чужой файл агент сначала сообщает об этом.
После получения результатов координатор проверяет diff, интеграцию и тесты, исправляет проблемы
и запускает полный применимый набор проверок этапа. Вложенное делегирование требует отдельного обоснования.

## Активация и ограничения

Проверять новые настройки в новой сессии из корня доверенного проекта: работающая сессия
может сохранять прежний набор ролей и лимиты. Если проект не доверенный, Codex может пропустить project config.
Не менять trust автоматически и не ослаблять управляемые ограничения.
Текущий интерфейс spawn может не предоставлять выбор custom role: тогда передать инструкции и параметры явно
либо использовать новую локальную Codex-сессию с поддержкой custom agents.
Не утверждать, что роль применена, без подтверждения среды. Если делегирование недоступно,
работать последовательно без процессов-имитаций.

Источники: [официальная документация субагентов](https://learn.chatgpt.com/docs/agent-configuration/subagents),
[справочник конфигурации](https://learn.chatgpt.com/docs/config-file/config-reference).
После обновления Codex перепроверять синтаксис через установленный CLI.

## Результат проверки подготовки

`codex --strict-config app-server --print-startup-config` завершился успешно с существующей
пользовательской конфигурацией. Глобальный ReadFold trust уже установлен в trusted; он не изменялся.
`git diff --check` прошёл; существующие HTML и правовые документы не изменены.
Git не отслеживает `.sensitive/` и локальные env-файлы; ignore-проверки прошли.
Содержимое секретов не читалось.

Полный smoke-test запуска каждой роли не выполнялся. Попытка локальной инспекции через
`codex debug prompt-input` завершилась ошибкой доступа Windows (os error 5).
CLI также предупреждает об отказе доступа к служебному каталогу arg0 в пользовательском Codex home.
Эти ограничения не мешают строгой проверке startup config, но распознавание всех шести ролей
и применение их параметров нужно подтвердить в новой сессии; загрузка модели не проверялась.
Приложение отсутствует, поэтому сборка и функциональные тесты к этой подготовке неприменимы.
