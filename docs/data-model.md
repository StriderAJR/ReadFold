# Данные приложения

Контент отделён от пользовательского состояния и не зависит от React, IndexedDB или Supabase.
`content.ts` содержит схемы Zod и выводимые типы `BookMetadata`, `Chapter`, `Sentence`, `Word`, `Kanji`,
`Grammar`, `Dictionary`. Поля JSON описаны в [book-format.md](book-format.md).
Внешний JSON проверяется до использования. Стабильные ID связывают каталог, главы, словари и записи пользователя.

Слово и его употребление — разные сущности. Словарь хранит исходную форму, чтение и общие значения;
предложение — конкретную форму, значение, склонение/спряжение и синтаксическую роль.
Иероглифы и грамматика имеют собственные ID и могут использоваться в нескольких книгах.
ID не пересекаются между тремя справочниками: например, слово `asa` и иероглиф `kanji.asa` — разные
учебные сущности. Грамматические ID имеют вид `grammar.topic`. `grammarRoles` в предложении дополняет
общее правило контекстным объяснением; синтаксическая роль слова хранится во вхождении `words[].role`.

`review.ts` — чистая логика тренировки. `createReviewTasks(words)` создаёт задания выбора значения:
`{id, wordId, prompt, answer, options}`. Порядок детерминирован по ID, принятые синонимы не используются
как неверные ответы. Одинаковые написания с разными записями пропускаются; без отвлекающих вариантов задания нет.
Генератору следует передавать изучаемые лексические слова, исключая частицы и записи, не подходящие для перевода вне контекста.

`scheduleReview(previous, rating, now)` принимает время в миллисекундах UTC и возвращает
`{repetitions, intervalDays, dueAt}`. `again` сбрасывает счётчик и назначает повтор через 10 минут;
`hard` увеличивает интервал в 1,2 раза (минимум день), `good` — в 2,5 раза (минимум день),
`easy` — в 3 раза (минимум 4 дня). Интервалы округляются до целого числа дней по 24 часа.
Это простой предсказуемый алгоритм, без заявления об использовании FSRS или SM-2. Сохранение результата выполняет слой приложения.
