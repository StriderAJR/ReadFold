# Локальное хранение и синхронизация

`LocalRepository` сохраняет неизменяемую операцию и запись outbox одной транзакцией IndexedDB.
Интерфейс должен дождаться `record`, прежде чем показывать успешное сохранение. Сетевой вызов не входит
в эту транзакцию. История операций остаётся после подтверждения сервера; удаляется только запись outbox.

Данные и курсор разделены по `ownerId` (внутренний ID приложения). Гость использует `guest`.
Вход и переключение аккаунта сами по себе не переносят данные. `mergeGuest(accountId)` вызывается только
после явного выбора пользователя: копирует события, сохраняет гостевой оригинал и атомарно записывает
соответствие исходного события новому UUID. Повторный вызов в той же локальной базе безопасен.
`importData(ownerId, unknown)` сначала проверяет весь экспорт через Zod и выполняет одну транзакцию.
Экспорт версии 1 содержит только операции выбранного владельца, без токенов и настроек подключения.

`reduceOperations` сортирует события по `createdAt`, затем по ID. Статусы обучения и отдельные поля
настроек используют последнее событие; вся история остаётся для диагностики конфликтов и восстановления.
Все отзывы сохраняются. Множество прочитанных предложений объединяется, последняя позиция хранится
отдельно от максимальной. Для корректного порядка между устройствами желательно правильное системное время;
конфликт при одинаковом времени разрешается лексикографическим порядком ID. Для одного устройства
метаданные хранят монотонное время события: максимум текущего времени и предыдущего времени плюс 1 мс.
Та же транзакция сериализует изменения разных вкладок, поэтому последовательное локальное действие
сохраняет порядок даже при одинаковом времени или переводе системных часов назад.

Перед сохранением и импортом проверяются ограничения сервера: ID операции/устройства до 128 символов,
ID сущности до 512 символов, компактный JSON payload до 48 КиБ с запасом относительно серверных 64 КиБ JSONB.
Не-JSON значения отклоняются. Learning/review имеют строгий набор известных полей; числовые поля
расписания ограничены безопасными конечными числами, произвольные дополнения не принимаются.
Это также исключает раздувание payload большими числовыми экспонентами при преобразовании JSONB.
Превышение лимита не создаёт операцию и outbox; ошибка не блокирует
отправку следующих корректных изменений. Словари состояния используют объекты без прототипа, поэтому
ID вроде `constructor` и `__proto__` обрабатываются как обычные ключи.

`SyncEngine` отправляет снимок готового outbox. Новые изменения, появившиеся во время отправки,
не подтверждаются этим запросом. После успешной отправки серверная история читается страницами;
каждая страница и курсор сохраняются атомарно. Чужой owner, изменение события с тем же ID или откат
курсора отвергаются. Сервер обязан принимать повтор одной операции идемпотентно и отвергать изменение
её содержимого. Web Locks координирует вкладки, когда API доступен; без него повторы безопасны благодаря
серверной идемпотентности. Отправка гостя отключена.

Ошибки транспорта содержат `status` и необязательный `retryAfter` (секунды или HTTP-дата).
401/403 устанавливают `auth-required`, 409 — `conflict`; ошибки сети, 429 и 5xx сохраняют outbox.
Следующая попытка записана в IndexedDB: экспоненциальная задержка до пяти минут с jitter, либо Retry-After.
Движок вызывается приложением при входе, восстановлении сети, локальном изменении и периодически;
он сам не держит таймеры. До истечения задержки push пропускается, pull остаётся доступным.
Действующая сессия транспорта должна соответствовать `ownerId`. Сервер проверяет owner каждого push;
receive повторно проверяет owner каждого события. При смене аккаунта старый вызов не может записать
данные другого владельца; операции уже отправленной части повторяются идемпотентно.

Таблица cache хранит отдельно загружаемые JSON книги. Версия Dexie 2 добавляет индексы категории и уровня,
версия 3 — время последнего события и агрегированные счётчики. Миграции не меняют операции,
outbox, курсоры и кеш версии 1.
Диагностика хранит максимум 100 агрегатов за последние семь дней: код из разрешённого списка,
категорию, уровень, HTTP-статус, первое и последнее время и число повторов; тексты ошибок,
содержимое чтения, email и токены не записываются. `diagnosticSummary` суммирует счётчики.
Экспорт заново применяет разрешённый список полей и кодов даже для старых сохранённых записей.
`exportDiagnostics` выдаёт только эту таблицу. Очистка браузерных данных удаляет локальные несинхронизированные
изменения; экспорт позволяет пользователю сохранить резервную копию.

Проверки в `src/application/sync.test.ts`: откат при ошибке outbox, изоляция владельцев,
повторный перенос гостя и импорт, проверка внешних данных, конфликты, изменение во время push,
HTTP 401/403/409/429/503, восстановление и сохранение задержки после открытия новой базы.
